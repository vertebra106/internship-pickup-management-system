# 从运行结果理解代码

这份项目是可运行的学习起点。接触过数组和 ArrayList，不代表已经掌握封装、异常和文件持久化；需要自己预测、运行、解释并修改后再判断。

## 1. 枚举：状态只能二选一

先读 `ExpressStatus`。`PENDING` 和 `PICKED_UP` 是两个固定值，分别显示“待取件”和“已取件”。如果用任意字符串，很容易出现“已领取”“已取件”混用。枚举把可选值限制住。磁盘保存英文常量名，界面使用中文标签。

预测：一条记录取件后再次取件，应当保持什么状态？运行演示步骤 10 验证。

## 2. 类与对象：描述一种事物，创建具体实例

`Express` 是一种快递记录的定义。`new Express(...)` 创建一条具体记录，比如单号 DEMO001；另一条 DEMO002 是另一个对象。类规定有哪些字段，对象保存各自的字段值。

`String` 用来保存单号、电话、取件码，即使看起来是数字，也属于标识或文本。`"01234567890"` 的首位零必须保留，不能为了方便转成整数。

## 3. 构造方法：创建时就保证基本有效

构造方法与类同名，没有返回类型。创建 Express 时把六项数据传进来，先检查空值、控制字符、长度、电话格式和状态，再形成有效对象。

基本格式与唯一性不同：一个对象能检查自己的电话是否合法，但需要查看其他记录才能知道单号是否重复，因此唯一性放在 Service。

## 4. 封装：只能通过规定入口改变系统

`private` 字段不允许其他类随意访问；getter 提供读取。`final` 字段创建后不能重新赋值。这里刻意没有 setter：修改姓名或状态时创建一个新 Express，再由 Service 保存提交。

原因：如果先 `old.setStatus(...)` 再保存，保存失败时旧内存已经变了。现在旧对象不变，失败时直接保留旧列表即可。

`final` 引用并不普遍等于对象不可变；本项目的实体字段都是不可变的 String 和枚举，也没有修改方法，才形成不可变实体。

## 5. ArrayList：长度可以变化的列表

`ArrayList<Express>` 表示“只能放 Express 对象的可变长度列表”。`add` 加入一条、`remove` 删除一条、`set` 替换某位置、`size` 查看数量；增强 for 循环逐条查看。

本项目按单号查询时，从第一条开始比较，找到返回，否则返回 `null`。因此调用者必须检查 `null`，不能直接取字段。

`new ArrayList<>(records)` 复制列表，但不是递归复制每个对象。两份列表开始时引用同一批 Express；因为 Express 不可变，所以安全。修改时只替换候选列表中的对象，不改旧对象。

`List<Express>` 是列表的接口类型，`ArrayList` 是具体实现。这里没有创建额外的业务接口层。`findAll` 返回新列表，界面即使对它执行 `clear()`，也不会清空内部数据。

思考：为何修改时不能仅仅复制列表，然后对共享对象调用 setter？试着用两张列表指向同一个对象的图说明。

## 6. 异常：把失败原因交给能够处理它的代码

- `IllegalArgumentException`：数据不合法，例如重复单号、无效电话。
- `IllegalStateException`：数据读取异常后处于只读保护，当前不允许写入。
- `IOException`：文件读取或保存失败。
- `NoSuchElementException`：控制台输入结束，例如输入重定向内容耗尽。

`throw` 表示主动报告失败；`throws IOException` 表示方法可能把文件异常交给调用方；`try/catch` 表示在这里处理某类失败。UI 负责给用户可读提示，不把错误当成功。异常后本次操作结束，菜单继续。

Repository 读取单行失败会记警告并继续；整个文件读取失败会记警告并停止读取。Service 看到警告后统一禁止写入，以保护原文件。

## 7. 文件读写：程序退出后，数据仍在磁盘

内存列表随程序退出消失，所以要落盘。`Path.of("data", "express.tsv")` 表示相对工作目录的数据路径。把运行工作目录换掉，会读到另一份文件；因此脚本固定目录，启动也打印完整路径。

`Files.newBufferedReader/Writer` 使用 UTF-8。缓冲器减少细碎读写，`try-with-resources` 确保文件关闭，即使出现异常也会释放资源。

本项目一行一个记录，以制表符分列。`split("\t", -1)` 中的 `-1` 保留末尾空列，方便正确检查缺失字段。逗号和双引号没有特殊含义；制表符和换行被输入校验拒绝，所以不能把一个字段拆成多列多行。

保存步骤：完整写入同目录临时文件 → 关闭文件 → 原子替换目标文件。文件系统不支持原子移动时让操作失败。它减少半写内容风险，不表示实现了数据库事务或断电保护。

## 8. 六个类怎样配合

以“取件”为例：

1. Main 创建 Repository、Service 和 UI。Service 构造时读取文件。
2. ConsoleUI 读取菜单 6 和取件码，将码交给 `service.pickUp`。
3. Service 查找对象，检查是否存在、是否已经取件。
4. Service 创建状态为 PICKED_UP 的新对象，放进候选列表。
5. Repository 将候选列表保存到文件。
6. 保存成功后，Service 用候选列表替换旧列表；UI 才打印成功。

如果第 5 步失败，就不会执行第 6 步，旧内存还保持待取件。测试专门制造文件失败来验证这一点。

修改取件码的关键判断：别人已经用了这个码就拒绝；找到的记录如果正好是自己则允许。唯一性在全部记录范围检查，包括已取件记录。

## 9. 阅读顺序和验证任务

按 `ExpressStatus → Express → ExpressRepository → ExpressService → ConsoleUI → Main → ExpressTests` 阅读，每次只推进一个任务：

| 顺序 | 关注点 | 完成证据 |
| --- | --- | --- |
| 1 | 状态与对象 | 口述一条记录的六个字段以及新增状态 |
| 2 | 封装和构造 | 解释为什么电话是 String、为什么没有 setter |
| 3 | 存储 | 找到六列格式，说明制表符为何被拒绝 |
| 4 | 业务 | 跟踪新增与取件，指出保存失败后的执行路径 |
| 5 | 交互 | 解释删除 Y 确认和无效菜单后如何继续 |
| 6 | 测试 | 修改一个预期让测试失败，再恢复并确认通过 |

测试中的 lambda（`()->...`）是“把一段稍后执行的操作传给方法”，用于组织测试，不必先掌握它才能阅读主程序。`CheckedAction` 只是测试辅助类型。测试用 `check` 主动抛错，不依赖默认关闭的 Java `assert`。
