# 面试演示流程

## 准备

运行 `test.ps1` 确认测试通过，再运行 `run.ps1`。演示仅用虚构数据。若已有同名记录，使用另一组单号和取件码；若想从空数据开始，先退出并将原 `data/express.tsv` 复制到安全位置，再移走原文件。不要在程序运行时编辑文件。

说明项目定位：“这是校园取件业务的 Java 控制台学习实现。业务层负责规则，存储层负责文件读写。当前使用 ArrayList 和 UTF-8 TSV，没有数据库。”不要声称全部代码都是自己独立编写；只说明实际掌握、修改和验证过的内容。

## 按顺序操作（约 5～8 分钟）

| 步骤 | 输入/操作 | 预期结果 |
| --- | --- | --- |
| 1 | 菜单 2（空文件时） | 暂无快递记录 |
| 2 | 菜单 1；`DEMO001`、`张同学`、`01234567890`、`A-01`、`校园快递` | 成功并保存，默认待取件 |
| 3 | 菜单 1；`DEMO002`、`李同学`、`12345678901`、`A-02`、`公司,"分部"` | 成功；逗号和引号不会破坏格式 |
| 4 | 菜单 2 | 显示全部六字段；第一条电话前导零保留 |
| 5 | 菜单 1，重复 `DEMO001`，其他字段合法 | 提示单号已存在；记录数不变 |
| 6 | 菜单 1，单号 `DEMO003`，取件码 `A-01`，其他字段合法 | 提示取件码已存在 |
| 7 | 菜单 3 → 1 → `A-01`；再 3 → 2 → `DEMO002` | 两种查询均定位正确 |
| 8 | 菜单 4 → `DEMO001`；姓名 `张同学`、电话 `01234567890`、码 `A-02`、公司 `校园快递` | 修改失败，取件码冲突；旧码 A-01 仍可查询 |
| 9 | 重复修改，取件码改为 `B-01`，其他字段合法 | 修改成功；旧码 A-01 查不到，新码 B-01 查得到 |
| 10 | 菜单 6 → `B-01`；再重复一次 | 第一次成功变为已取件；第二次拒绝重复取件 |
| 11 | 菜单 0；重新运行 `run.ps1`；查询 `DEMO001` | 姓名、电话、B-01 和已取件状态仍在 |
| 12 | 菜单 5 → `DEMO002` → `n`；查看全部 | 取消删除，记录仍在 |
| 13 | 菜单 5 → `DEMO002` → `Y`；退出重启后查询 | 删除已保存，查不到该记录 |
| 14 | 输入菜单 `abc`；查询不存在的单号 | 友好提示，仍能继续操作 |

新增/修改必须输入完所有字段才统一校验；输入错误会返回菜单，不会部分保存。

## 展示异常处理证据

运行 `test.ps1`，指出保存失败、读取坏行和真实进程重启的 PASS 项。测试在独立临时目录模拟“保存父目录变为普通文件”和“目标变为非空目录”，并验证新增、修改、删除、取件失败时内存保持不变，且不会输出成功。

如需现场手动演示坏行：退出程序，备份演示数据，在文件末尾添加单独一行 `broken`（保存 UTF-8 无 BOM），重启。应提示行号和只读模式，有效记录仍可查询，写操作被拒绝。退出后还原备份再启动。不要在唯一一份重要数据上做此演示。

## 面试官可能追问

- 为什么电话用 String？号码不参与算术，需保留前导零。
- 修改取件码如何查重？找到占用该码的记录，只有它属于当前单号时才允许。
- 保存失败如何保证一致性？候选列表使用新对象，先保存，成功后才替换内存列表。
- 为什么坏行时禁止保存？直接重写有效记录会悄悄丢弃被跳过的内容。
- ArrayList 为什么适合第一版？简单易读；查询线性、保存全量，不能据此宣称高并发能力。
- 为什么不是数据库事务？这里只是单进程中的文件保存与内存提交，没有数据库事务、多进程锁或断电恢复保证。

回答时结合源码与测试说明，不背诵自己还不能解释的实现。
